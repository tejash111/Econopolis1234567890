# ECONOPOLIS conventions — iPhone and separate native Mac targets

The later explicit user request authorizes a separate native macOS app alongside the iPhone application. `Econopolis` remains iPhone-only iOS 18+ with no Catalyst target. `EconopolisMac` is a native macOS 15+ target and shared scheme using the same source group and static EconopolisCore. The Mac app reuses the same RealityKit scene controller/resources and shared SwiftUI financial screens; no separate economic engine or copied app tree. Platform adapters belong in Presentation/MacCompatibility.swift, conditional UIKit lifecycle/color/haptics code and the Mac-specific persistence path. Mac builds never count as iPhone validation.
Mac verification: xcodebuild -project Econopolis.xcodeproj -scheme EconopolisMac -configuration Debug -derivedDataPath .build/mac -destination 'platform=macOS,arch=arm64' CODE_SIGN_IDENTITY=- build. Run .build/mac/Build/Products/Debug/EconopolisMac.app. Mac storage is Application Support/ECONOPOLIS-Mac/session.store; Keychain namespaces derive from org.econopolis.mac and are independent of the simulator. Do not show mobile-only haptic controls on Mac. Share CitySceneController and CityResources across ARView/RealityView; keep Canvas as an explicit fallback. Mac bottom navigation reuses the five iPhone destinations; do not replace the City with a simplified renderer by default. Native process launch is not proof of GUI interactions; record screen-capture/automation limits honestly.
